# Pop benchmark

- **Date:** 2026-11-01
- **Code:** commit `0f4873c`, with the pop effect and element animations ([ADR 0073](../decisions/0073-effects-animate-their-element.md))
- **Compare with:** [2026-10-23-v3-engine](2026-10-23-v3-engine.md), on the same machine with the same method and harness

## Summary
- No frame rate regressed. Every WebGL row, and every row up to 5000 particles, holds about 120 fps, as in the reference. At 20000 on Canvas 2D, the three effects in both runs are faster than in the reference: confetti 39.5 → 46.1 fps, emoji 41.5 → 51.0 and balloons 65.1 → 72.4.
- Confetti on WebGL at 20000 is busier: the main thread went from 48% to 55% busy (script 3.82 → 4.46 ms a frame), at the same 119.3 fps. The reference was recorded before confetti's paper fall ([ADR 0059](../decisions/0059-confetti-falls-like-paper.md)), and at 20000 on WebGL emoji and balloons cost the same or less per frame (script 2.70 → 2.62 and 3.23 → 3.20 ms), so the increase isn't attributed to `fire()`.
- Fireworks have no row in the reference, so they can't be compared. On WebGL they hold 120 fps to 20000 particles, with the main thread 26% busy. On Canvas 2D they fall to 90.7 fps at 20000.
- Pop holds about 119 fps on WebGL up to 20000 particles. Its 20000 row is the heaviest WebGL row in the run: p95 10.3 ms, 1.1% long frames, and the main thread 60% busy. On Canvas 2D it holds about 119 fps to 5000, and falls to 40.5 fps at 20000, near confetti's 46.1.
- No burst ran meaningfully past its lifetime. Bursts measure about 25 ms over nominal, as in the reference: pop's take 1525 ms for 1500. At 20000 on Canvas 2D, confetti and balloons run a frame or two longer (3058 and 5046 ms), and pop's median 17 ms longer (1542 ms), under a frame at 40.5 fps, with one run at 1567. Emoji and fireworks don't: 3033 and 3517 ms.
- Pop is the first effect with style recalculation time, 0.02 to 0.07 ms a frame, so the reference's "Style recalculation and layout are zero" no longer holds for it. The time is attributed to the button's element animation: the Stress test fires from its button, which shrinks away and springs back during each burst, and that is the only change to the DOM per frame that the other effects don't make. It wasn't measured with `bounce` off.
- Not measured, as in the reference: a machine without a usable GPU, where WebGL2 runs in software.

## Method
The method is the reference's, with five effects.

- **Harness.** `demo/bench/run.ts`, run with `pnpm bench` at the root ([ADR 0048](../decisions/0048-benchmark-script-in-demo.md)). It builds the library and the demo, serves the built site with Rsbuild's preview server, and drives the site's Stress test page through its controls ([demo README, Stress test](../../demo/README.md#stress-test)).
- **Bursts.** Each burst uses the effect's defaults apart from `count`. Confetti and emoji live up to 3000 ms, balloons 5000 ms, fireworks 3500 ms and pops 1500 ms.
- **Counts that aren't particles.** Fireworks count rockets and pops count stars, so the Stress test turns the particle count into those.
  - Fireworks get one rocket per 130 particles: 4, 38 and 154 rockets. A rocket peaks at about 126 live particles, so their counts are approximate.
  - Pops get one star per 2 particles: 250, 2500 and 10000 stars. A pop of N stars peaks at 2N + 6 particles at the defaults (a star and its streak each, 5 dots and the flash), so pop's rows peak at 506, 5006 and 20006 particles.
- **The element.** The harness clicks "Reward me" with `element.click()`, so `useReward` fires from the button and animates it. Pop's button, a 52 px circle on the Stress test, shrinks away and springs back during each burst ([ADR 0073](../decisions/0073-effects-animate-their-element.md)). No other effect animates its element.
- **Runs.** Each combination of effect, renderer and count runs in a fresh tab, with the renderer forced through `setRenderer` ([ADR 0033](../decisions/0033-strict-public-set-renderer.md)). The tab gets:
  - a 1.5 s settle delay;
  - a check that `requestAnimationFrame` isn't throttled;
  - one warm-up burst, which is not recorded;
  - a check that the readout names the forced renderer ([ADR 0047](../decisions/0047-burst-renderer.md));
  - 3 recorded bursts.

  The tables show the median of the 3.
- **Timing.** A burst runs from the click, made inside a frame callback, until the readout says the burst has ended. Frame timing comes from the harness's own `requestAnimationFrame` timestamps over that window. "Long frames" counts frames longer than 1.5 refresh intervals.
- **Main-thread time.** It comes from the Chrome DevTools Protocol `Performance.getMetrics`, read before and after each burst: `ScriptDuration`, `RecalcStyleDuration`, `LayoutDuration` and `TaskDuration`. "Other" is task time minus script, style and layout: mostly paint, compositing, and the Canvas 2D renderer's raster work. Costs are per frame.
- **What isn't counted.** Raster and GPU work on other threads isn't included. The page's own work is: the readout updates four times a second while a burst runs.

## Harness
`demo/bench/run.ts`. To repeat the run, install Chromium once with `pnpm --filter demo exec playwright install chromium`, then run `pnpm bench` at the root. Keep the Chromium window uncovered while it runs, because macOS throttles windows that are hidden. It writes the full results to `demo/bench/results.json`, which git ignores.
