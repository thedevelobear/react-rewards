## Goal
v2.1.0 is about 500 lines of TypeScript, built with Rollup 2, ESLint 8, TypeScript 4.6 and Yarn, with no tests, CI or demo. v3 modernises the tooling, moves to TypeScript 7, replaces the DOM animations with a GPU-rendered particle engine that new effects are cheap to add to, and adds a preview site. Backward compatibility is not a goal. The toolchain, engine and API choices are in [ADR 0001](../decisions/0001-v3-direction.md).

## How the work is run
- v3 merges into the integration branch `feat/v3-scaffolding`, which merges into `master` once, at the release ([ADR 0003](../decisions/0003-integration-branch.md)). The site's redesign is the last PR on it ([ADR 0058](../decisions/0058-site-redesign-before-the-release.md)). After that, work branches off `master` ([ADR 0056](../decisions/0056-work-after-release-branches-off-master.md)).
- Each PR below is a `v3/NN-topic` branch made with `--no-track` (see `AGENTS.md`). PRs land one at a time, each after the previous one has merged.
- Each PR updates this plan and adds an ADR for each decision ([ADR 0002](../decisions/0002-docs-as-decision-record.md)). Anything unclear is asked before it is decided.

## Steps

### 1. Tooling (PR 1)
- pnpm replaces Yarn, and the lockfiles are regenerated. Biome 2 replaces ESLint, Prettier and Babel. Rslib replaces Rollup.
- `package.json`: `"type": "module"`, an exact `packageManager` ([ADR 0008](../decisions/0008-toolchain-version-pins.md)), one `exports` entry ([ADR 0004](../decisions/0004-esm-only-output.md)), `files: ["dist"]`, `"sideEffects": false`, peer `react >=18`, and `prepublishOnly` running the typecheck, tests and build.
- `tsconfig.json`: `target ES2022`, `moduleResolution Bundler`, `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `noEmit`, and `isolatedDeclarations` ([ADR 0017](../decisions/0017-isolated-declarations.md)).

Notes:
- TypeScript 7 ships no classic compiler API, so Rslib declares types with the native binary. Declarations mirror `src/` rather than being bundled. attw runs its own TypeScript 5.6.
- TypeScript 7 doesn't infer `rootDir`. `tsconfig.json` sets `"rootDir": "./src"` and includes only `src`, so `rslib.config.ts` is linted but not type-checked.
- Rsbuild imports an SVG as a URL. Markup is imported with `?raw`, declared in `src/svg.d.ts`.
- Biome's Markdown formatter is off, so docs keep their layout, and `pnpm-lock.yaml` is excluded.

### 1b. Naming and folder rules
Adapted from [Robin Wieruch's React folder structure](https://www.robinwieruch.de/react-folder-structure/). They apply to `src/` and `demo/src/`.

1. **Files and folders are kebab-case.** Identifiers stay conventional: PascalCase for components and types, camelCase for the rest.
2. **Folders and component names are singular** (`effects/confetti/`).
3. **Plural is for collections only:** top-level grouping folders (`effects/`, `components/`) and files holding several definitions (`types.ts`).
4. **Files are named by role inside a folder:** `confetti/effect.ts`, `use-reward/hook.ts`, `test.ts`, and `dom-test.ts` for tests that need a DOM ([ADR 0022](../decisions/0022-happy-dom-tests.md)).
5. **`index.ts` is the public API only.** Other code imports from the folder. `src/index.ts` is the package's API.
6. **Co-location.** Everything for one unit lives in its folder, at most two levels deep.
7. **Promotion and demotion.** Code used by one unit stays in it. Once two units need it, it moves up to a shared folder, and back down if only one is left.
8. **One-way dependencies.** Shared folders never import from effects or hooks. Effects don't import each other, and `use-reward` composes them.
9. **Absolute path aliases** (`@/core/...`).
10. **Namespace imports for util groups** where they read better.

Biome's `useFilenamingConvention` and `useNamingConvention` enforce the naming, and `noRestrictedImports` the dependencies. `components/` isn't used in `src/`, because effects aren't React components. The demo has `components/<name>/` (each `index.ts`, `component.tsx`, `style.css`), `hooks/<name>/`, `data/` and `fixtures/` ([ADR 0045](../decisions/0045-fixture-page.md)).

### 1c. Engine
v2 appended one `<span>` per particle inside the trigger, so the browser restyled every node each frame, and the trigger's `overflow` or `transform` could clip particles. Its physics counted frames, so speed depended on the display. Each call ran its own animation loop that nothing cancelled. The three effects were near-copies, and nothing tree-shook.

**Rendering.** WebGL2 draws instanced sprites, one draw call per run of bursts with the same blend mode ([ADR 0034](../decisions/0034-merge-neighbouring-batches.md)). Canvas 2D is the fallback, drawing from the same atlas with `drawImage`, with no particle cap ([ADR 0050](../decisions/0050-no-canvas-particle-cap.md)). DOM nodes, WebGPU, simulating on the GPU and libraries such as PixiJS were rejected: they keep the clipping problem, aren't supported widely enough, make effects write shaders, or outweigh the library.
- Both renderers implement `{ kind, canvas, resize, draw(frame), clear, dispose }`. A frame is the shared atlas and one batch per burst.
- The first burst tries WebGL2, then Canvas 2D, each on a fresh canvas. `setRenderer` forces one, and a forced one never falls back ([ADR 0033](../decisions/0033-strict-public-set-renderer.md)).
- There is no per-particle tint, because Canvas 2D can't tint cheaply. Colour is baked into sprites.
- A new draw feature goes into both renderers before an effect uses it. The parity spec checks this.

**Layout**
```
src/
  index.ts                    # public API
  core/                       # framework-agnostic, no React
    define-effect/            # defineEffect() and the effect contract's types
    fire/                     # fire(): the stage, burst lifecycle, cancel, finished
    pool/                     # structure-of-arrays particle pool
    simulation/               # one burst's stepping (ADR 0018)
    loop/                     # one shared requestAnimationFrame loop, clamped dt
    atlas/                    # sprite sources packed into one atlas
    renderer/                 # renderer interface, selection, overlay canvas
    renderer-webgl/           # WebGL2 instanced sprites, context loss
    renderer-canvas/          # Canvas 2D fallback
    origin/                   # ref, element or point to viewport coordinates
    motion/                   # prefers-reduced-motion
    math/                     # seedable rng, easings, scalar helpers
  effects/
    confetti/  emoji/  balloon/
  react/
    use-reward/               # thin hook over fire()
  test-utils/                 # fakes shared by tests
```

**Effect contract** ([ADR 0019](../decisions/0019-particle-contract.md), [guide](../guides/adding-an-effect.md))
```ts
export const confetti = /* @__PURE__ */ defineEffect({
  name: 'confetti',
  blend: 'normal',  // or 'additive'
  defaults: { count: 50, size: 10, colors, angle: 90, spread: 45, velocity: 1500, drag: 3, gravity: 900, lifetime: 3000 },
  sprites: (config) => [{ shape: 'rect', color, width: 8, height: 5 }],
  spawn: (p, config, rng, index) => { /* initial velocity and sprite */ },
  update: (p, dt, config, ctx) => { /* change velocity; ctx.spawn() adds children */ },
});
```
- `dt` is in seconds, clamped to 1/30 s. Effects change velocity, and the simulation moves particles. `math.accelerate` and `math.damp` are exact at any frame rate, and public ([ADR 0053](../decisions/0053-public-math-helpers.md)).
- The contract has `spawn` and `update` only ([ADR 0005](../decisions/0005-effect-contract-scope.md)). Its functions are method signatures, so any `Effect<C>` is an `Effect` ([ADR 0052](../decisions/0052-effects-generic-over-effect.md)).
- Effects import only `core/define-effect`, `core/math` and their own folder. Their `test.ts` may run a simulation.
- Each built-in `defineEffect` call is marked pure ([ADR 0055](../decisions/0055-pure-effect-definitions.md)).

**Public API**
```tsx
const ref = useRef<HTMLButtonElement>(null);
const { reward, isAnimating } = useReward(ref, confetti, { count: 120 }, { zIndex: 10 });
<button ref={ref} onClick={() => reward()}>Reward me</button>
```
- `useReward(target, effect, config?, options?)` ([ADR 0041](../decisions/0041-hook-burst-options-argument.md)). `reward` is stable ([ADR 0040](../decisions/0040-stable-reward.md)), returns the burst, and stacks ([ADR 0042](../decisions/0042-reward-returns-burst.md)). As an event handler it fires from the pointer ([ADR 0044](../decisions/0044-reward-handles-pointer-events.md)).
- `fire(effect, { origin, config, zIndex, onComplete, respectReducedMotion, seed })` returns `{ cancel, finished, renderer }` ([ADRs 0023](../decisions/0023-fire-options-beside-config.md), [0025](../decisions/0025-cancel-skips-on-complete.md), [0047](../decisions/0047-burst-renderer.md)).
- Shared config names, in physical units ([ADR 0024](../decisions/0024-physical-config-units.md)): `count`, `size`, `colors`, `angle`, `spread`, `velocity`, `drag`, `gravity`, `lifetime`. Effects add their own, such as `emojis` and `rotate`.

**Runtime**
- One fixed, `pointer-events: none`, `aria-hidden` canvas on `document.body`, shared by all bursts and sized by `ResizeObserver` at the device pixel ratio. `zIndex` defaults to 2147483647 ([ADR 0029](../decisions/0029-default-z-index.md)).
- It is created on the first burst, hidden when idle, and removed with its renderer 5 s after the last burst. One WebGL context serves the page.
- A lost context ends the running bursts and replaces the canvas ([ADR 0036](../decisions/0036-context-loss-replaces-canvas.md)).
- Reduced motion skips bursts unless `respectReducedMotion` is `false`. The hook cancels its bursts on unmount.
- Importing touches no `window`, so it is safe during SSR. The build adds a `"use client"` banner.

**Tests**
- Node: the pool, loop, atlas packer and every effect, with a seeded generator. Frame-rate tests simulate 1 s at 30, 60 and 144 Hz and compare the end states.
- Node: the Canvas 2D renderer against a recording 2D context, and the WebGL2 renderer against a recording WebGL2 context.
- happy-dom: the overlay and the hook ([ADRs 0022](../decisions/0022-happy-dom-tests.md), [0043](../decisions/0043-hook-tests-with-testing-library.md)).
- Headless Chromium, on `fixtures.html` ([ADR 0045](../decisions/0045-fixture-page.md)): drawing, one canvas for concurrent bursts, context loss, no clipping in an `overflow: hidden` and `transform` wrapper, cancel on unmount, fallback, and WebGL against Canvas 2D parity ([ADR 0035](../decisions/0035-parity-diff-with-pixelmatch.md)).

**Benchmarks**
- [v2 baseline](../benchmarks/2026-10-22-v2-baseline.md): balloons fall to 8.5 fps at 2000 elements, and slow frames stretch a 10 s burst to 70 s.
- [v3 engine](../benchmarks/2026-10-23-v3-engine.md): WebGL holds 120 fps at 20000 particles for every effect. Canvas 2D holds 120 fps at 5000 and 40 to 65 fps at 20000. Every burst keeps its time.

**Notes**
- `createRng` is mulberry32 with its state kept to 32 bits. A test locks the sequence for seed 1.
- `defineEffect` types `defaults` as `C`, not `Readonly<C>`, which would infer literal types and reject every override.
- Growing the pool replaces its arrays, so `pool.fields.x[pool.alloc()] = v` writes to the old array.
- Age and life are compared as stored float32s, so a life of whole steps ends on the step that reaches it.
- The loop requests the next frame before running callbacks, so one that throws doesn't stop it.
- The stage steps every burst in one frame callback and draws their batches in the order they started. A burst holds the overlay while its sprites load, so the atlas can't be cleared under it.
- An emoji's atlas box is 1.25 times its font size, and every sprite is clipped to its box. The atlas grows from 256 to 2048 px by copying, so held regions stay valid. A full atlas rejects the load, with no eviction.
- A hidden canvas measures 0 × 0, so the overlay re-measures on every acquire, which also catches a changed pixel ratio.
- WebGL builds each quad from `gl_VertexID`, with 11 floats per particle uploaded once a frame. It has no multisampling. A one-texel margin of the atlas's padding softens edges instead. The atlas is uploaded premultiplied, and `dispose()` frees the context with `WEBGL_lose_context`.
- Headless Chromium runs WebGL2 on SwiftShader, with no extra flag. Parity measured 1% differing pixels, and the spec allows 5%.
- The balloon SVG states its size, 976 by 3040, because an image without one draws differently across browsers.
- The hook stores its latest arguments in an insertion effect, which React 18 has and which doesn't warn during server rendering. A burst fired while Strict Mode reconnects effects is cancelled a microtask later only if the hook is still unmounted.
- Without the React plugin, SWC compiles JSX for the classic runtime, so the `dom` project sets the automatic one.
- Rspack's persistent cache in `node_modules/.cache/rspack` can abort a build with `ModuleGraphModule ... not found` after files are deleted and restored. Deleting the cache fixes it.

### 2. Tests and CI (PR 2)
- `rstest.config.ts` extends the Rslib config through the adapter. It includes `src/**/test.{ts,tsx}` in Node and `src/**/dom-test.{ts,tsx}` in happy-dom, because the adapter would otherwise pick happy-dom for the `web` target, and the default glob misses role-based names.
- `.github/workflows/ci.yml` runs on Node 26 from `.nvmrc` ([ADR 0011](../decisions/0011-node-26-in-ci.md)), set up by `pnpm/setup` ([ADR 0014](../decisions/0014-pnpm-setup-action.md)): `biome ci`, typecheck, tests, build, the demo's typecheck, publint, attw `--profile esm-only`, size-limit with no budget ([ADR 0013](../decisions/0013-size-limit-report-only.md)), and the Playwright specs.
- size-limit's preset bundles with Rolldown, leaves React out, and reports gzip.

### 3. Preview site (`demo/`) (PRs 9 to 11)
A workspace package that imports the built library ([ADR 0031](../decisions/0031-demo-imports-built-package.md)), built with Rsbuild and React 19 ([ADR 0027](../decisions/0027-react-demo.md)), with plain CSS custom properties and `shiki` for code. Its design decisions are in [`demo/README.md`](../../demo/README.md).

**Look.** The site's visual direction, colour tokens and theme are in [`demo/README.md`](../../demo/README.md), under "Visual direction". PR 14 replaced the first look, which followed reactbits.dev's shape and type with the blog's colours (step 6).

**Pages.** The header, sidebar, Getting started, page title, preview, Preview and Code tabs, props panel, code blocks, props table, pager and Stress test are described in [`demo/README.md`](../../demo/README.md). The props panel is generated from each effect's controls in `demo/src/data/effects/<name>.ts`, so a new effect needs one demo file. The site deploys to GitHub Pages ([ADR 0049](../decisions/0049-pages-deploy-from-integration-branch.md)).

**Notes**
- Rsbuild 2 takes `html.template` as a function of the entry, so only the site uses `index.html` and its pre-paint script.
- Fontsource declares each script with a `unicode-range`, so an English page loads only the Latin files.
- `Controls<C>` maps each config field to a control for its type, so a missing or wrong control is a type error.
- Sliders draw their track as two background layers, because Chromium's `accent-color` drew the empty part dark grey in light mode.
- The colour picker's + tile listens for the native `change` event, because React's `onChange` fires on every `input`.
- shiki's three chunks (72 kB gzipped) load after first paint.
- `output.assetPrefix: 'auto'` keeps the font URLs working under `/react-rewards/`. `'./'` resolves them against `static/css/`.
