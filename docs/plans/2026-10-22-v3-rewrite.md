## Context
`react-rewards` (v2.1.0) is a small library, about 500 lines of TS. It exports `useReward` and the `confetti`, `balloons` and `emoji` functions (`src/index.ts`).
The tooling is dated:
- Rollup 2 with esbuild, dts and svg plugins (`rollup.config.js`)
- ESLint 8 with the airbnb and wesbos configs, plus Prettier 2 and Babel (`.eslintrc`)
- TypeScript 4.6 (the `package.json` pin is `^4.6.2`)
- Yarn (`yarn.lock`)

There are no tests, no CI and no demo. The README has only GIFs. The working tree had stray `package-lock.json` and `pnpm-lock.yaml` files and an uncommitted `tsconfig.json` edit. PR 1 cleans them up.

Goal: modernise the tooling, move to TypeScript 7, replace the DOM-span animation code with a GPU-rendered particle engine that new effects can be added to cheaply (backward compatibility is not a goal), and add a small preview site for the effects. The site uses the blog palette from thedevelobear.com. The layout follows reactbits.dev: a live demo on top, a props panel beside it, and a code snippet below.

## Decisions
The choices below were accepted from the original plan ([ADR 0001](../decisions/0001-v3-direction.md)). Later ADRs refine them.

| Area | Choice | Why |
|---|---|---|
| Package manager | **pnpm** | Strict and fast, with the best workspace support. The demo can live in the same repo as `demo/`. Bun is a runtime, and its package-manager benefits here are marginal. |
| Lint and format | **Biome 2** | Replaces ESLint, all the airbnb/wesbos/prettier plugins, Prettier and the Babel parser with one dependency and one `biome.json`. |
| Library build | **Rslib** | It is built on Rsbuild, so the lib and the demo share one toolchain. It does ESM output plus `.d.ts` (ESM only, [ADR 0004](../decisions/0004-esm-only-output.md)). Fallback: **tsdown** (Rolldown-based, a near drop-in for tsup) if Rslib's dts output misbehaves. |
| Demo site build | **Rsbuild** | React plugin, fast HMR, static output. |
| TypeScript | **7.x** | Native compiler (`tsc` still works). Used for type-checking only. Rslib emits the declarations. |
| Rendering | **WebGL2 instanced sprite renderer with a Canvas 2D fallback; simulation in TypeScript** | WebGL2 draws every particle in one call per blend mode and scales to tens of thousands. Canvas 2D runs the same particle batches where WebGL2 is unavailable. Effects stay plain TS with no shaders. Details and rejected options in step 1c. |
| Tests | **Rstest** (`@rstest/core`, plus `@rstest/adapter-rslib`) in Node, plus a **Playwright** browser smoke test | Rstest is in the same Rstack family, so it reuses the Rslib config and has a Jest-compatible API. It is pre-1.0, which is acceptable here. The simulation, pool, loop and atlas packer are pure and run in Node. WebGL cannot run in jsdom, so the renderer is checked in headless Chromium against `demo/`. |
| CI | GitHub Actions | `pnpm i --frozen-lockfile`, then `biome ci`, `tsc --noEmit`, `rstest run`, and the build. |

### 1b. Naming and folder rules
Adopted from [Robin Wieruch's React folder structure](https://www.robinwieruch.de/react-folder-structure/), adapted to this library. They apply to `src/` and `demo/src/`.

**Naming rules**
1. **Files and folders are kebab-case** (`use-reward/`, `date-time.ts`). Identifiers in code stay conventional: components and types in PascalCase, functions and variables in camelCase.
2. **Folders and component names are singular** (`effects/confetti/`, not `confettis/`). Nested children follow the same rule.
3. **Plural is for collections only.** Top-level grouping folders are plural (`effects/`, `hooks/`, `utils/`, `components/`). Bundle files holding several definitions are plural (`types.ts`, `constants.ts`).
4. **Role-based file names inside a folder.** The folder carries the name, the file carries the role: `confetti/effect.ts`, `use-reward/hook.ts`, `animation/util.ts`, and `test.ts` for tests. No dotted names like `Confetti.types.ts`.
5. **`index.ts` is the public API only.** It re-exports what outside code may use. Other code imports from the folder, never from the implementation file. `src/index.ts` is the package's public API.
6. **Co-location.** Everything for one unit lives in its folder (implementation, `types.ts`, `constants.ts`, `test.ts`, assets such as `balloon.svg`). Maximum two levels of nesting.
7. **Promotion and demotion.** Code used by one unit stays inside it. Once two or more units need it, move it up to the shared folder (`utils/`, `types/`). If a shared piece ends up serving one unit, move it back down.
8. **One-way dependencies.** Shared folders (`utils/`, `types/`) never import from effects or hooks. Effects (`confetti`, `emoji`, `balloons`) do not import from each other. `use-reward` composes them.
9. **Use absolute path aliases** (`@/utils/...`), configured once in `tsconfig.json` and the Rslib/Rsbuild configs.
10. **Namespace imports for util groups** where it helps readability, e.g. `import * as animationUtil from '@/utils/animation'`.

**Target `src/` layout.** It is shown in full under step 1c (`core/`, `effects/`, `react/`), and follows the rules above: kebab-case, singular folders, `index.ts` as the public API, role-based file names and co-located tests. The v2 files are deleted in PR 5 rather than renamed, so there is no rename step ([ADR 0007](../decisions/0007-no-rename-step.md)). Apply the rules to the new code from the start.

`components/` is not used in `src/` because effects are not React components. It is reserved for the demo's UI.

**Demo layout** (`demo/src/`): `main.tsx`, `app.tsx`, `components/{preview,props-panel,code-block,nav}/` (each with `index.ts`, `component.tsx`, `style.css`), and `data/effects/<name>.ts`. The file list in step 3 follows these names.

**Enforcement**
- Biome rule `style/useFilenamingConvention` set to kebab-case, plus `style/useNamingConvention` for identifiers. A violation fails `biome ci`.
- Rules 1 to 10 apply to all new code. The v2 files are exempt through a temporary Biome override, which PR 5 removes together with the files ([ADR 0007](../decisions/0007-no-rename-step.md)).

### 1c. New animation engine (GPU-rendered particles, TypeScript simulation)

Backward compatibility is not a goal for v3. The animation code is replaced, not ported: a new engine, a new effect-authoring contract and a clean public API. The v2 files (`Confetti.ts`, `Emoji.ts`, `Balloons.ts`, `helpers.ts`, `useReward.ts`) are deleted in PR 5, so until then they only need to keep compiling.

**Problems in v2 that the rewrite removes**
- One `<span>` per particle, appended inside the trigger element. Every frame the browser restyles every node because JS writes `transform`, `scale` and `opacity` inline. Cost grows linearly with `elementCount`.
- The trigger is the parent, so its `overflow`, `transform` or `contain` can clip or misplace particles.
- Physics counts frames (`lifetime` in ticks) and `fps` only throttles, so speed depends on the display and on dropped frames.
- Each call starts its own `requestAnimationFrame` loop. Nothing cancels it, `setIsAnimating` can fire after unmount, and `prefers-reduced-motion` is ignored.
- Every effect re-implements the same create, update and cleanup code (three near-identical files). A new effect means copying a file.
- `useReward` imports every effect, so nothing tree-shakes.

**Rendering options**
| Option | Verdict |
|---|---|
| DOM nodes (tuned or via Web Animations) | Rejected. One node per particle and the clipping problem remain. |
| Canvas 2D overlay as the only renderer | Good and simple. Fine up to a few thousand sprites, but glow, additive blending and trails get expensive as effects grow more complex. **Kept as the fallback renderer.** |
| **WebGL2 instanced sprite renderer** | **Primary renderer.** Draws every particle in one draw call per blend mode. Additive blending and large counts are cheap. The cost is contained in one renderer module (see below). |
| WebGPU | Rejected. Support is still patchy and it adds complexity with no benefit at this scale. |
| Simulation on the GPU (one shader per effect) | Rejected. Fastest at runtime, but every effect would need GLSL, and stateful behaviour (trails, collisions, spawning children) is hard. That is the opposite of easy authoring. |
| PixiJS, three.js, tsparticles | Rejected. Large dependencies for what is a sprite batch, and they would dwarf the library. |

**Why WebGL2 does not make the library much more complex**
- Every effect reduces to "a batch of textured quads": position, rotation, scale, alpha, sprite id and a blend mode. Confetti, emoji, balloons, snow, stars, coins, hearts, firework sparks and glowing trails all fit that model. One generic renderer serves all of them. Effect authors never write GLSL or touch the GL API.
- Simulation stays in plain TypeScript over typed arrays. It is easy to write, debug and unit-test in Node. Tens of thousands of particles per frame should be realistic for this design, to be confirmed by the benchmark below.
- Sprites are drawn with the Canvas 2D API (emoji, SVG, shapes, gradients, text) and packed into one atlas texture. Complex looks come from 2D drawing code, not shaders.
- The renderer sits behind a small interface, and a Canvas 2D implementation of it ships as the fallback (next section), so no effect depends on WebGL.
- Honest costs: some GL boilerplate (one module, a few hundred lines), context-loss handling, a second renderer to keep in step with the first, no jsdom support for the WebGL path (tests are split, see below), and a slightly larger bundle (a `size-limit` budget is set after measuring, not promised up front).

**Renderer fallback (WebGL2 to Canvas 2D)**
- Both renderers implement one interface, roughly `{ kind, resize(width, height, dpr), draw(frame), clear(), dispose() }`. The `frame` is renderer-agnostic: the pool's typed arrays, the live count, the shared atlas and the blend-mode ranges. The simulation, the atlas and every effect are shared. Only drawing differs.
- Selection at the first burst: try `getContext('webgl2')`; if that fails (unsupported, blocklisted GPU, context creation error), use Canvas 2D. A canvas element cannot change context type once created, so the overlay creates a fresh canvas for the other renderer. If neither is available the burst is skipped and `onComplete` still fires, because rewards are decorative.
- `setRenderer('auto' | 'webgl' | 'canvas')` (default `'auto'`) forces a renderer. The tests use it, and the demo gets a toggle so you can compare them.
- The Canvas 2D path draws each sprite with `setTransform` and `drawImage` from the same atlas canvas, with `globalAlpha` for alpha and `globalCompositeOperation = 'lighter'` for additive blending. It is expected to be slower at high counts, which the benchmark will show.
- **Contract change for parity:** per-particle `tint` is removed. Canvas 2D cannot tint a sprite cheaply, so colour is baked into sprites instead (confetti declares one sprite per colour, and a particle picks one with `sprite`). Brightness, flip shading and similar effects use `alpha` and non-uniform `scale`. This keeps every effect rendering identically on both paths.
- Any new draw feature (a new blend mode, per-particle attributes) must be implemented in both renderers before an effect may use it. A parity check in the browser tests (below) enforces this.
- The fallback has no particle cap unless the benchmark shows it needs one.

**Architecture**
```
src/
  index.ts                    # public API
  core/                       # framework-agnostic, no React imports
    define-effect/            # defineEffect() and the types effects code against (the contract)
    fire/                     # fire(): burst lifecycle, cancel, finished promise
    pool/                     # particle pool: structure-of-arrays Float32Array, grows as needed
    loop/                     # one shared requestAnimationFrame loop, clamped delta time
    atlas/                    # sprite sources to a packed atlas texture, cached by key
    renderer/                 # renderer interface, selection (auto / webgl / canvas), overlay canvas lifecycle
    renderer-webgl/           # WebGL2 instanced sprite renderer, shaders, context loss
    renderer-canvas/          # Canvas 2D fallback renderer (drawImage from the atlas)
    origin/                   # target (ref or element) or {x, y} to viewport coordinates
    motion/                   # prefers-reduced-motion
    math/                     # rng (seedable), easing, vector helpers
  effects/
    confetti/  emoji/  balloons/     # one folder each; the only place new effects are added
  react/
    use-reward/               # thin hook over fire()
```

**Effect contract** (the stable surface that all future effects are written against; the sketch is illustrative):
```ts
export const confetti = defineEffect({
  name: 'confetti',
  blend: 'normal',                           // or 'additive' for glows and sparks
  defaults: { count: 50, size: 8, colors, angle: 90, spread: 45, velocity: 35, drag: 0.06, gravity: 900, lifetime: 3000 },
  sprites: (config) => [{ shape: 'rect' }],  // or { emoji }, { svg }, { draw(ctx, size) }
  spawn: (p, config, rng, index) => { /* set initial position, velocity, sprite (one per colour) */ },
  update: (p, dt, config, ctx) => { /* mutate p; ctx.spawn() can add children (trails, sub-bursts) */ },
});
```
- A particle exposes `x`, `y`, `vx`, `vy`, `rotation`, `scale` (plus separate x and y scale for flips and squash), `alpha`, `sprite`, `age`, `life` and a few free float slots for effect-specific state.
- `dt` is in seconds, so effects are frame-rate independent. The loop clamps `dt` (for example to 1/30 s) so a stalled tab does not teleport particles when it resumes. Use `Math.pow(drag, dt)`-style maths for decay.
- The 3.0 contract has `spawn` and `update` only. There is no `onPointerDown` hook (balloon click-to-pop is dropped), and continuous emitters (a spawn `rate`) are deferred until an effect needs them ([ADR 0005](../decisions/0005-effect-contract-scope.md)).
- Effects import only from `core/define-effect` and `core/math`. Biome `noRestrictedImports` enforces this, so renderer, pool and atlas internals can change without touching effects.
- Adding an effect means one folder (`index.ts`, `effect.ts`, `types.ts`, `test.ts`) plus one demo entry. This is written up in `docs/guides/adding-an-effect.md` (PR 12).

**New public API**
```tsx
const ref = useRef<HTMLButtonElement>(null);
const { reward, isAnimating } = useReward(ref, confetti, { count: 120 });
<button ref={ref} onClick={() => reward()}>Reward me</button>
```
- `useReward(target, effect, config?)`. The target is a ref or an element. The string `id` lookup is dropped. Effects are imported by name, so unused ones tree-shake, and custom effects made with `defineEffect` work identically.
- `reward(origin?)` fires from the target's centre in viewport coordinates, or from `{ x, y }` (for example the pointer position).
- Vanilla: `fire(effect, { origin, config })` returns `{ cancel(), finished }`.
- One consistent config for every effect: `count`, `size`, `colors`, `angle`, `spread`, `velocity`, `drag`, `gravity`, `lifetime` (milliseconds), `zIndex`, `onComplete`. Effects add extras (`emojis`, `rotate`). The v2 names (`elementCount`, `elementSize`, `decay`, `fps`, `position` and so on) are dropped. The exact names are finalised when the first effect is ported (PR 5), and the README gets a short "from v2" mapping table.
- Peer deps: `react >=18`. The hook has no React 19-only requirements.

**Runtime behaviour**
- One `position: fixed; inset: 0; pointer-events: none; aria-hidden` canvas on `document.body`, shared by all concurrent bursts, sized to the viewport at device pixel ratio (kept in sync by `ResizeObserver`). `zIndex` comes from the config.
- Created on the first burst. When idle it is cleared and hidden (`display: none`), and the renderer (the GL context, for WebGL) is disposed after an idle timeout, so repeated bursts do not pay context creation each time and an idle page pays nothing.
- A single WebGL context for the whole page (browsers cap the number of live contexts), with `premultipliedAlpha` and no `preserveDrawingBuffer`.
- Context loss and restore: on loss, active bursts end cleanly and call `onComplete`. On the next burst the WebGL renderer is rebuilt (program, buffers, atlas texture). If WebGL2 cannot be re-created, the Canvas 2D fallback takes over.
- `prefers-reduced-motion: reduce` skips the effect and fires `onComplete`. A `respectReducedMotion` option (default `true`) opts out.
- `cancel()` stops a burst. The hook cancels its bursts on unmount, so no state updates run after unmount, and React Strict Mode double effects cannot leave duplicate canvases.
- Safe to import during SSR (no `window` access at import time). The build adds a `"use client"` banner for Next.js and RSC.

**Testing split**
- Node (Rstest, no DOM): the pool, the loop, the atlas packer, and every effect's `spawn` and `update`, using the seeded RNG. Includes frame-rate independence (simulate 1 s at 30, 60 and 144 Hz and compare end states within a tolerance) and a state snapshot after N steps per effect.
- Node, Canvas 2D renderer: run against a mock 2D context to assert the `setTransform` and `drawImage` calls, alpha and blend mode for a known frame.
- Real browser (Playwright, headless Chromium, run against `demo/`, which starts as a bare page in PR 5, see [ADR 0006](../decisions/0006-bare-demo-as-e2e-target.md)): the canvas is non-blank during a burst and removed or hidden afterwards, one canvas for concurrent bursts, recovery after `WEBGL_lose_context`, no clipping inside an `overflow: hidden` and `transform` wrapper, and cancel on unmount.
- Renderer parity and fallback, in the same browser run (PR 6): render one seeded, deterministic frame with `setRenderer('webgl')` and again with `setRenderer('canvas')`, then compare the two images within a tolerance. Also check that WebGL2 being unavailable (the context request is stubbed to fail) falls back to Canvas 2D and still plays the effect.

**Benchmark and budgets**
- Baseline first: v2.1.0 at `elementCount` 50, 500 and 2000. **Done** in PR 1: [2026-10-22-v2-baseline](../benchmarks/2026-10-22-v2-baseline.md). Confetti and emoji hold about 110 fps at 2000 elements but keep the main thread 68 to 80% busy. Balloons fall to 35 fps at 500 and 8.5 fps at 2000. Because v2's physics counts frames, slow frames stretch the animation (10 s became 70 s).
- Repeat on the new engine at 500, 5000 and 20000 particles with the demo's fps readout, once per renderer (use the demo's renderer toggle). Keep all sets of numbers in the PR 11 description and in `docs/benchmarks/`. If the Canvas 2D fallback is unusable at high counts, add a particle cap for it.
- Set the `size-limit` budget from the measured size of the engine, hook and three effects (PR 8). The v2 README's 3.6kB claim is only a reference point.

**Visual direction.** The styling follows reactbits.dev (fonts, radii, spacing, surfaces, motion), measured from its live stylesheet on 2026-10-21, with the colours taken from the blog. The tokens are re-implemented in `demo/src/styles/tokens.css`. No reactbits CSS or assets are copied.

**Typography (from reactbits)**
- **Geist** for all UI text and **Geist Mono** for code, prop names and values. Both are self-hosted through `@fontsource-variable/geist` and `@fontsource-variable/geist-mono` (5.3.0), so there is no Google Fonts request. This replaces the blog's Roboto and Libre Baskerville.
- Weights 400, 500 and 600, mostly 500. 900 only for the occasional display word.
- Sizes:
  - UI text: 13 to 14px
  - Labels: 12px
  - Tags: 9 to 11px
  - Sidebar items: 0.85rem
  - Section titles: 1.6rem, bold, `letter-spacing: -0.01em`
  - Page title: 3rem, weight 600, `letter-spacing: -2px`, `line-height: 1`
- Default `letter-spacing: -0.01em` on UI text.

**Shape and spacing (from reactbits)**
- Radius tokens: `--radius-xs: 6px`, `--radius-sm: 10px`, `--radius-md: 12px`, `--radius-lg: 14px`, `--radius-xl: 24px`, `--radius-full: 999px`.
- Nested radius rule: an inner element's radius is the outer radius minus the padding. For example, the 14px code frame with 4px padding contains 9px panels (`calc(var(--radius-lg) - 5px)`).
- Controls: 32px tall, 7px radius, 12px text. Tags: 16px tall, 4px radius, 9px weight-600 text. Pills and avatars: `--radius-full`.
- 1px borders define surfaces. Light mode uses no drop shadows. Dark mode uses a 1px top-inset highlight (`inset 0 1px 0 #ffffff12`) on raised surfaces.
- Header height 60px.

**Motion (from reactbits)**
- `--ease-out: cubic-bezier(.23, 1, .32, 1)`.
- Durations: 0.12s for press, 0.15s fast, 0.2s base, 0.3s slow.
- Hover states change colour and nudge position (for example sidebar items move `translateX(2px)` and turn accent-coloured).
- `prefers-reduced-motion` turns the UI transitions off. The particle effects already honour it (step 1c).

- Focus ring: `2px solid var(--accent)` with a 2px offset in both themes.

**Dark mode with a header switcher**
- The switcher offers three states: system, light and dark. The default is system (`prefers-color-scheme`). The choice is stored in `localStorage` and applied as `data-theme` on `<html>`.
- An inline script in `index.html` sets `data-theme` before first paint to prevent a flash of the wrong theme. All `localStorage` access is wrapped in `try/catch`.
- Every colour is a token in `tokens.css`, defined under `:root` (light), `:root[data-theme="dark"]`, and `@media (prefers-color-scheme: dark)` for `:root:not([data-theme="light"])`.
- The `shiki` code theme follows the site theme.
- The particle canvas is theme-independent. The demo's default effect colours are checked on both backgrounds.

Layout (similar to the reactbits component page, simplified):
- **Header** (60px, 1px bottom border): the logo, a GitHub link, and the **theme switcher** (system, light, dark).
- **Sidebar:** the effect list (Confetti, Emoji, Balloons, and future ones from the effect registry). Items use 0.85rem weight-400 text with the hover nudge. The active item shows the gradient text and a 2px gradient bar. On phones it becomes a horizontal scroll of pills.
- **Page title:** the effect name at 3rem weight 600 with `-2px` tracking, plus a one-line description in `--text-muted`.
- **Preview container:** full width, 1px border, `--radius-lg` (14px), `--card` background, and the reactbits **dot grid**: `radial-gradient` 1px dots on a 20px grid in `--text-dimmed`, masked to fade towards the edges. A centred primary "Reward me" button (gradient, ink text) wired to `useReward`, a replay button, and the fps and renderer readout as a small mono tag in the corner.
- **Props panel:** reactbits "preview options" style. A 3-column grid with 8px gaps and 14px by 12px padding, a 1px border, and a 9px radius inside a `--surface` frame. Sliders, switches and colour swatches use the 32px, 7px-radius control style. It covers the unified config (`count`, `size`, `colors`, `angle`, `spread`, `velocity`, `drag`, `gravity`, `lifetime`, and the per-effect extras). The panel is generated from a per-effect controls definition in the demo, so a new effect needs one demo file and no panel code. The preview re-renders with the live config.
- **Code section:** a reactbits "code frame": a `--surface` frame with 14px radius and 4px padding, holding a 9px-radius code panel in Geist Mono. It has Preview and Code tabs, a generated snippet reflecting the current props, and a copy button. A separate frame holds the `pnpm add react-rewards` install command, with a pnpm, npm, yarn and bun switch.
- **Props table** at the bottom (name, type, default): Geist Mono for names and values, 1px row dividers in `--border-subtle`, and a soft hover on rows.
- A **renderer toggle** (auto, WebGL, Canvas 2D) that calls `setRenderer`, with the active renderer shown next to the fps readout.
- A **stress control**: a particle-count slider (up to 20000) and a live fps readout, to show the engine's headroom. It also supplies the benchmark numbers in step 1c.
- A fixture card inside an `overflow: hidden` and `transform` wrapper, to prove the effect is not clipped.
